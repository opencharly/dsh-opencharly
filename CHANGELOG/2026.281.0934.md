# 2026.281.0934 — feat(rearm): re-arm an ACTIVE goal on the human turn, and raise the goal budget

## Summary

Two halves of one operator-asked deliverable: a goal that silently stops counting is fixed at its
cause, and the budget that made it bite is raised in the bundle patch.

**1. The seam (the fix).** DSH disarms a goal on every `agent/created`
(`dsh-goal/lib/index.js:594-596`) — a safety property, because `agent/created` fires for a fresh
**post-resume process** too, so re-arming there would let a stale goal silently continue work no human
re-authorized. The cost was a magic word.

This plugin now re-arms on the **human turn** instead. `session/event` carries the session's event
stream, and `user/message` is the only user-shaped event in it, so a post-resume process emits none: a
resumed process stays disarmed while a human turn re-arms. The safety distinction survives and the
magic word goes away.

The route is the `goals` service's own documented transition, `resume(agent, goal.revision)`
(`dsh-goal/lib/index.js:686`), which commits the activation edge `"armed"` through the same guard the
CLI uses (`:686-698`) — so this seam cannot invent a state the rest of the system does not understand.
That guard permits an already-`active` goal (exactly the case here: phase `active`, activation
`disarmed`) and it also permits `paused` and `blocked`, which this seam deliberately **does not**
re-arm: a human who paused or blocked a goal must not have it restarted by their next sentence. Those
phases get one log line saying so.

Behind a `rearm` toggle in `DEFAULT_CONFIG` beside `gates`/`soul`/`watch`.

**2. The budget.** `cordis.patch.yml` gains a **bare** `- id: goal` row with
`defaultMaxGoalRounds: 1500`. The bare form TARGETS the row of that id that an earlier layer
already contributes rather than adding one (`insert:` is for adding, which is what the
`dsh-opencharly` entry above does); `config:` replaces the row's whole block, and `dsh-goal`'s
entire Config is that single key, so the replacement costs nothing.

**The id is `goal`, not `dsh-goal` — and the first revision of this PR got that wrong.** The base
bundle's row is `- id: goal` / `name: '@deepseek-ai/dsh-goal'`
(`@deepseek-ai/dsh-base/cordis.patch.yml:313-314`); the id and the module name are different
strings, and targeting the name matched **nothing** — composed with DSH's own composer the base row
came back unchanged, with no error and no duplicate, so the raise silently vanished. That is fixed,
and the evidence is in `## How tested` §3.

**3. Four seams now, on every surface that says so.** The plugin documented "three seams" in the
README (heading, table, prose, layout, config example) and in a code comment, and CI's own header
repeated it. All are updated here.

**4. This revision is the review fix, in one commit.** Three findings, all mine: (a) an unrelated
whitespace-only hunk that collapsed `function createState() {` / `  return {` onto one line — no gate
in this repo can see it, and it is reverted; (b) the body claimed "7 new cases" where the file has
**6**, now corrected to match the file rather than the other way round; (c) the budget half **did not
work** — it targeted the module name instead of the row id, which is a silent no-op, now fixed and
evidenced by running the composer (§3 below).
