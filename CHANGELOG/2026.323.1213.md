## Summary

The DSH leg of opencharly/opencharly#1140. Head: `6f85a5973ef25c87697472f79e62a156b43b95b6` — 11 files, +548 −175, in two commits: `c084d572` (the change) and `6f85a597` (round 2: the live proof against real GitHub).

The umbrella replaced the shell watcher family (`marketplace/scripts/gh_watch.sh` and its `--auto-rearm`) with ONE TypeScript watcher every harness binds, `node scripts/gh/cli.ts watch` (opencharly/opencharly#1160). This plugin's watch seam still spawned `gh_watch.sh` at a 60 s interval — which the new CLI's 300 s poll floor refuses — so it moves to the CLI, and takes over the one job `--auto-rearm` did: re-arming after a wake.

1. **The CLI, run by the DSH process's own node.** `spawnWatcherProcess` runs `process.execPath <cli> watch …` instead of `bash <script>`, and its outcome now carries the exit `code` and the last stdout `line` (the wake). The config defaults move to `scripts/gh/cli.ts`, a 300 s interval, and events `comment,verdict,merged,closed,conflict,stall` (`conflict` wakes on a PR that conflicts with its base, which gets no validator run at all).
2. **The re-arm after each wake** (`decideRearm` in `lib/watch.js`, the same rule as the umbrella's pi binding):
   - an item whose STATE event fired is **retired**. A state event fires from the arm baseline and `--no-arm-wake` does not suppress it, so re-arming such an item re-fires it at once — the hot-loop the pi binding shipped and opencharly/opencharly#1163 fixed. Which events are state events is the engine's own `STATE_EVENTS`, imported at runtime from the checkout's `scripts/gh/lib/watch.ts` (`loadEngineStateEvents`); this plugin names none of them;
   - any other wake, and a timeout, re-arm the remaining items with `--no-arm-wake`;
   - exits 5, 6, 7, 8 and 143 (usage/API, lock, rate limit, initial poll, takeover) stop the watch, with the reason logged.
3. **`autoRearm` is deleted** from the config, the types and the README (R5): the CLI has no such switch, and the seam does the re-arming.
4. **`test/live-watch.test.js`** runs the plugin's real wiring — `apply()`, `spawnWatcherProcess`, `loadEngineStateEvents`, nothing injected — with the umbrella's real `scripts/gh/` (from `DSH_OPENCHARLY_UMBRELLA`) against **real GitHub**: it watches `opencharly/dsh-opencharly#3`, a PR that merged on 2026-10-08 — a state that never changes, read-only — and asserts the real `MERGED` state event retires the item: one arm, and the watch ends. Its job controller refuses after five starts, so a broken seam fails fast without spending the API budget in a loop. It skips visibly without the umbrella checkout or without a GitHub credential (R8).
